## 1. Змагання і цей набір

IEEEXtreme — це 24-годинне змагання з програмування для команд, у яких до трьох
студентів — членів IEEE. Задачі розміщено на CS Academy; розв’язок — це один файл
з вихідним кодом, який читає стандартне введення і пише у стандартне виведення. Кожна задача має багато
тестів, і **кожен пройдений тест приносить бали**, тож повільний, але правильний
розв’язок усе одно отримує бали. Кілька задач мають відкриту постановку (лише виведення, оптимізація,
code golf), а деякі є інтерактивними.

Що вимагає архів (основна тема кожної з 252 задач; подробиці в
[tasks.md](tasks.md)):

| Тема | Задач | Тема | Задач |
|---|---:|---|---:|
| Графи | 30 | Повний перебір / перебір із поверненням | 9 |
| Математика і теорія чисел | 25 | Бітові операції | 7 |
| Динамічне програмування | 24 | Конструктивні задачі | 7 |
| Дерева | 23 | Обробка тексту і даних | 7 |
| Жадібні алгоритми і сортування | 19 | Інтерактивні | 6 |
| Структури даних | 19 | Зворотна розробка | 6 |
| Рядки | 18 | Теорія ігор | 4 |
| Реалізація і моделювання | 17 | Двійковий пошук | 3 (+8 як допоміжний інструмент) |
| Комбінаторика і ймовірності | 17 | Геометрія | 11 |

Якщо враховувати й допоміжні теми, переважають динамічне програмування (DP; 48 задач), математика (47), графи (38) і
структури даних (37). Комбінаторика з модульною арифметикою стала поширеною
починаючи з 15.0.

**Робота з набором.** Напишіть розв’язок, підключивши бібліотеку, протестуйте його
локально, а потім зберіть в один файл:

```sh
cc -std=c11 -O2 -Wall -I lib solution.c -lm -o sol   # компіляція (-lm для math.h)
./sol < sample.in                                   # перевірка
python3 tools/bundle.py solution.c > submit.c       # один файл для надсилання
```

Заголовні файли бібліотеки призначені для читання: кожен починається зі списку своїх
функцій, а кожна функція має коментар про те, що вона робить і яка її складність.

## 2. Мова C для змагань

### 2.1 Шаблон

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef long long ll;

#define MAXN 200005
static int a[MAXN];              /* великі масиви: глобальні/статичні, ніколи не локальні */

int main(void) {
    int n;
    if (scanf("%d", &n) != 1) return 0;
    for (int i = 0; i < n; i++) scanf("%d", &a[i]);
    ll sum = 0;
    for (int i = 0; i < n; i++) sum += a[i];
    printf("%lld\n", sum);
    return 0;
}
```

[`lib/common.h`](../../lib/common.h) містить ті самі базові речі (`ll`, `MIN`, `MAX`,
`SWAP`, `INF`, `LINF`, `MOD`).

### 2.2 Введення і виведення

- `scanf` повертає кількість прочитаних елементів. Читання тестів до кінця введення:
  `while (scanf("%d %d", &a, &b) == 2) { ... }`.
- Цілі рядки: `fgets(buf, sizeof buf, stdin)` залишає `'\n'`; видаліть його так:
  `buf[strcspn(buf, "\r\n")] = 0;` (це також видаляє `'\r'` у файлах Windows).
- Змішування `scanf("%d")` і `fgets`: після числа решта його рядка лишається непрочитаною,
  тому перший `fgets` повертає порожній рядок. Прочитайте його й відкиньте.
- Формати: `%d` int, `%lld` long long, `%llu` unsigned long long, `%s` слово,
  `%c` символ (використовуйте `" %c"`, щоб пропустити пробіли), `%lf` для читання double, `%.6f`
  для його виведення.
- Великі вхідні дані (10^6 чисел і більше): [`io.h`](../../lib/io.h) приблизно вдесятеро
  швидший за `scanf` (`read_int`, `read_ll`, `read_word`, `read_line`).
  Не змішуйте його зі `scanf` і ніколи не використовуйте в інтерактивних задачах.

### 2.3 Розміри цілих типів і переповнення

| Тип | Діапазон | Типове використання |
|---|---|---|
| `int` | ±2.1·10^9 | індекси, лічильники |
| `long long` | ±9.2·10^18 | суми, добутки, відповіді |
| `unsigned long long` | 0 … 1.8·10^19 | геші, бітові маски на 64 елементи |
| `__int128` (GCC/Clang) | ±1.7·10^38 | добутки двох 64-бітних значень |
| `double` | ~15 значущих цифр | геометрія, ймовірності |

- `int * int` переповнюється ще до присвоєння: пишіть `(ll)a * b`.
- «Виведіть відповідь за модулем 10^9+7»: беріть `% MOD` після **кожного** додавання і
  множення; після віднімання додайте `MOD` перед `%`: `((x - y) % MOD + MOD) % MOD`.
- `abs` призначена для `int`; для `long long` використовуйте `llabs`.
- У C `-7 / 2 == -3` і `-7 % 2 == -1`; у [`util.h`](../../lib/util.h) є
  `floor_div` і `ceil_div`.

### 2.4 Пам’ять і рекурсія

Локальні масиви розміщуються на стеку (часто 1–8 МБ): локальний `int a[1000000]` спричиняє збій програми.
Оголошуйте великі масиви як `static` або глобальні; вони ініціалізуються нулями. Глибока
рекурсія (DFS на шляху з 10^5 вершин) теж може спричинити переповнення стека, тому
алгоритми бібліотеки для графів і дерев ітеративні. Якщо у вхідних даних багато тестів,
не забувайте очищати глобальні масиви між ними.

### 2.5 Яка швидкість достатня

Розраховуйте приблизно на 10^8 простих операцій за секунду. За обмеженнями можна
вгадати очікувану складність:

| n до | Допустимо | Типовий алгоритм |
|---|---|---|
| 10 | O(n!) | перебір усіх перестановок |
| 20–25 | O(2^n · n) | підмножини, DP на бітових масках, «зустріч посередині» (40) |
| 500 | O(n^3) | алгоритм Флойда–Воршелла, DP на відрізках |
| 5 000 | O(n^2) | двовимірне DP, усі пари |
| 10^5 – 10^6 | O(n log n) | сортування, дерева відрізків, алгоритм Дейкстри |
| 10^7 – 10^8 | O(n) | лінійні проходи, решето |
| 10^18 | O(log n) або O(1) | формули, двійковий пошук, швидке піднесення до степеня |

### 2.6 Числа з рухомою комою

Уникайте їх, якщо можна обійтися цілими числами (порівнюйте `a*a < b`, а не `sqrt`). Якщо
без них не обійтися, порівнюйте з допуском `fabs(x - y) < 1e-9`, виводьте з точністю,
якої вимагає задача, і пам’ятайте про `long double` для додаткових цифр.

### 2.7 Тестування по-професійному

1. Запустіть приклади, потім граничні випадки: n = 1, усі значення однакові, максимальні значення,
   від’ємні значення, порожні рядки.
2. Напишіть повільний повний перебір і порівнюйте результати на випадкових малих вхідних даних (стрес-тест):

```sh
for i in $(seq 1 500); do
  python3 gen.py $i > in.txt                   # випадковий малий тест
  ./fast < in.txt > out1; ./brute < in.txt > out2
  cmp -s out1 out2 || { echo "differs on test $i"; cat in.txt; break; }
done
```

3. Під час налагодження компілюйте з перевірками: `cc -g -fsanitize=address,undefined ...`
   виявляє звернення за межі масивів і переповнення.

### 2.8 Стратегія на 24 години

Прочитайте всі задачі якомога раніше; відсотки розв’язань в архіві ([tasks.md](tasks.md)) показують,
що деякі задачі виглядають страшними, але насправді легкі, а деякі короткі — дуже складні.
Спершу надішліть правильний повний перебір, щоб отримати часткові бали, а потім покращуйте розв’язок.
Розподіліть роботу в команді за темами і залиште одного учасника відпочилим для нічної зміни.

## 3. Сортування і пошук

### 3.1 Сортування за допомогою `qsort`

```c
int cmp_int(const void *a, const void *b) {        /* цілі числа за зростанням */
    int x = *(const int *)a, y = *(const int *)b;
    return (x > y) - (x < y);                      /* ніколи не пишіть "return x - y": переповнення */
}
qsort(arr, n, sizeof(int), cmp_int);
```

Сортування структур за кількома ключами (з [`examples/intervals.c`](../../examples/intervals.c)):

```c
typedef struct { ll start, end; } Talk;

static int by_end(const void *a, const void *b) {
    const Talk *x = a, *y = b;
    if (x->end != y->end) return (x->end > y->end) - (x->end < y->end);
    return (x->start > y->start) - (x->start < y->start);
}
qsort(t, n, sizeof(Talk), by_end);
```

`qsort` працює за O(n log n), але не є стабільним; якщо порядок рівних елементів
важливий, додайте початковий індекс як останній ключ. Рядки: сортуйте масив `char *` за допомогою
`strcmp` (`cmp_str` у [`sort.h`](../../lib/sort.h)).

Споріднені інструменти в [`sort.h`](../../lib/sort.h): `unique_int` (вилучає дублікати),
`compress` (замінює значення їхнім рангом 0..m-1 — це потрібно, перш ніж використовувати значення
як індекси масиву), `count_inversions` (сортування злиттям, O(n log n); це також
мінімальна кількість обмінів сусідніх елементів, що впорядковує масив), `kth_smallest`
(швидкий вибір (quickselect), у середньому O(n)).

### 3.2 Двійковий пошук

У відсортованому масиві `lower_bound_int(a, n, x)` — це перший індекс, для якого
`a[i] >= x`, а `upper_bound_int` — перший, для якого `a[i] > x`; їхня різниця дорівнює
кількості копій `x`. (Архів: *The Twin Occurrence Quest*.)

**Двійковий пошук за відповіддю** — ще важливіша ідея. Якщо питання «так/ні»
`ok(x)` монотонне — ні, …, ні, так, …, так, — то найменше
підхоже `x` знаходять за O(log діапазону) перевірок. Типові формулювання: «мінімізувати
максимум», «максимізувати мінімум», «найменший час, за який…». З
[`examples/bs_answer.c`](../../examples/bs_answer.c) (розбити масив щонайбільше на
k частин, мінімізуючи найбільшу суму частини):

```c
static int ok(ll limit) {              /* чи можна розбити так, щоб усі частини були <= limit? */
    int parts = 1;
    ll cur = 0;
    for (int i = 0; i < n; i++) {
        if (a[i] > limit) return 0;
        if (cur + a[i] > limit) { parts++; cur = 0; }
        cur += a[i];
    }
    return parts <= k;
}
...
printf("%lld\n", bs_first_true(0, total, ok));
```

Для дійсних чисел виконуйте фіксовану кількість ітерацій (`bs_real`, 100 поділів навпіл).
**Тернарний пошук** знаходить мінімум функції, яка спершу спадає, а потім
зростає (`ternary_min_int`, `ternary_min_real` у [`search.h`](../../lib/search.h)).

## 4. Жадібні алгоритми

Жадібний алгоритм робить локально найкращий вибір і ніколи його не переглядає. Він
правильний лише тоді, коли спрацьовує **аргумент обміну**: візьміть будь-який оптимальний розв’язок
і покажіть, що заміна його частини на жадібний вибір не погіршує результат. Типові
шаблони:

| Ситуація | Жадібне правило |
|---|---|
| Найбільше інтервалів, що не перетинаються | беріть той, що закінчується найраніше ([`intervals.c`](../../examples/intervals.c)) |
| Покрити відрізок найменшою кількістю інтервалів | серед тих, що починаються до непокритої точки, беріть той, що сягає найдалі |
| Роботи з крайніми термінами, одинична тривалість | рухайтеся в часі, тримайте купу доступних робіт, виконуйте ту, що має найраніший крайній термін (*Doctor's Appointments*) |
| Мінімізувати максимальне запізнення | сортуйте за крайнім терміном |
| Розбити відсортовані значення на K груп | розрізайте в місцях K−1 найбільших проміжків (*Dog Walking*) |
| Вартість злиттів (Гаффман) | завжди зливайте два найменші (купа) |
| Зробити значення різними кроками ±1 | відсортуйте, потім посуньте кожне значення одразу вище за попереднє |

Якщо ви не можете довести жадібне правило, перед надсиланням перевірте його порівнянням
з повним перебором на малих вхідних даних.

## 5. Префіксні суми, два вказівники, ковзні вікна

**Префіксні суми** відповідають на запит «сума a[l..r]» за O(1): `p[0] = 0, p[i+1] = p[i] + a[i]`,
сума = `p[r+1] - p[l]`. У двовимірному випадку (`prefix2d_build`, `rect_sum` у
[`grid.h`](../../lib/grid.h)) сума будь-якого прямокутника — це чотири звертання до масиву.

**Масиви різниць** роблять протилежне: багато офлайн-оновлень «додати v до a[l..r]»
перетворюються на `d[l] += v; d[r+1] -= v`, а один прохід префіксних сум відновлює масив.
На дереві той самий прийом працює для шляхів за допомогою найнижчого спільного предка (LCA; *Tree Fun*).

**Два вказівники.** Коли умова монотонна щодо обох кінців вікна,
просувайте правий кінець уперед, а лівий підтягуйте теж лише вперед — O(n) замість
O(n²). З [`examples/two_pointers.c`](../../examples/two_pointers.c)
(найдовший блок із сумою ≤ budget, невід’ємні значення):

```c
for (int l = 0, r = 0; r < n; r++) {
    sum += a[r];                        /* вікно — це a[l..r] */
    while (sum > budget) sum -= a[l++];
    best = MAX(best, r - l + 1);
}
```

**Монотонний стек / дек** ([`linear.h`](../../lib/linear.h)): наступний більший
елемент, скількох людей бачить людина в ряду (*Long Lines*), найбільший
прямокутник у гістограмі (*Rectangles and arrays*), максимум кожного вікна
довжини k ([`examples/sliding_max.c`](../../examples/sliding_max.c)), переходи динамічного
програмування (DP) у межах вікна. Кожен індекс додається і вилучається один раз: O(n).

## 6. Структури даних

| Вам потрібно | Використовуйте | Вартість | Бібліотека |
|---|---|---|---|
| LIFO / FIFO / обидва кінці | стек на масиві, циклічна черга / дек | O(1) | `linear.h` |
| Багаторазово брати найменший (найбільший) елемент | двійкова купа | O(log n) | `heap.h` |
| «Чи траплявся x?», підрахунок, ідентифікатори для імен | геш-таблиця | O(1) у середньому | `hashmap.h` |
| Об’єднувати групи, «чи в одній групі?» | система неперетинних множин (DSU) | ~O(1) | `dsu.h` |
| Оновлення в точці + сума на префіксі/відрізку, k-й елемент | дерево Фенвіка | O(log n) | `fenwick.h` |
| Додавання на відрізку + сума на відрізку | два дерева Фенвіка | O(log n) | `fenwick.h` |
| Оновлення в точці + мінімум/максимум/НСД/будь-яка асоціативна операція на відрізку | дерево відрізків | O(log n) | `segtree.h` |
| Додавання / присвоєння на відрізку + сума / максимум на відрізку | дерево відрізків із відкладеним оновленням (lazy propagation) | O(log n) | `segtree.h` |
| Статичний мінімум / максимум / НСД на відрізку | розріджена таблиця (sparse table) | O(1) на запит | `sparse.h` |
| Префікси слів, пара з максимальним XOR | префіксне дерево (trie), двійковий trie | O(довжина) | `trie.h` |

**Купа.** `heap_push(&pq, key, id)` / `heap_pop(&pq)` повертає найменший ключ.
Для max-купи додавайте `-key`. Оголошуйте купу як `static` (вона велика).

**DSU** зберігає ліс; `dsu_find` іде до кореня (з діленням шляху навпіл), а
`dsu_union` підвішує менше дерево під більше. Варіант із парністю
(`pdsu_*`) зберігає, чи є два елементи «однаковими», чи «різними», — і виявляє непарні
цикли онлайн (*Odd Cycle Check*).

**Дерево Фенвіка** (індексація з 1): `fen_add(i, v)` і `fen_sum(i)` = a[1]+…+a[i].
Якщо `a[v]` — скільки разів трапляється значення `v`, то `fen_sum(v)` рахує менші
елементи (інверсії, ранги), а `fen_lower_bound(k)` знаходить k-й найменший.

**Дерево відрізків.** Листки зберігають масив, кожна внутрішня вершина об’єднує двох своїх
синів. `segtree.h` використовує компактну форму «знизу вгору» для будь-якої асоціативної
операції, яку задають двома макросами перед підключенням файлу:

```c
#define SEG_OP(a, b) ((a) < (b) ? (a) : (b))   /* мінімум на відрізку */
#define SEG_ID LINF                            /* нейтральний елемент: op(x, ID) = x */
#include "segtree.h"
```

Дерево з відкладеним оновленням (`lz_*`) не виконує оновлення на відрізку одразу: вершина, що повністю
покриває відрізок оновлення, зберігає відкладену операцію і передає її синам лише тоді, коли
вони знадобляться наступній операції. [`examples/segtree_lazy.c`](../../examples/segtree_lazy.c)
обробляє запити «додати», «присвоїти», «сума» і «максимум» (архів: *Corporation*).

**Sqrt-декомпозиція / алгоритм Мо** (немає в бібліотеці): розбийте масив
на блоки розміром √n; для офлайн-запитів на відрізках відсортуйте їх за парою (блок l, r) і
рухайте два вказівники — загалом O((n + q)√n).

## 7. Динамічне програмування

Динамічне програмування (DP) = рекурсія + запам’ятовування відповідей підзадач. Рецепт:

1. **Стан**: що потрібно знати про частковий розв’язок (індекс, залишкова
   місткість, останній вибір, маска використаних предметів…).
2. **Перехід**: як стан будується з менших станів.
3. **Базові випадки**.
4. **Порядок**: обчислюйте стан після станів, від яких він залежить (цикли), або використовуйте
   рекурсію з мемоїзацією.
5. **Відповідь**: у якому стані (станах) вона міститься.

Пам’ять/час = кількість станів × кількість переходів з одного стану.

### 7.1 Класичні типи

| Тип | Стан | Приклади з архіву | Бібліотека |
|---|---|---|---|
| Рюкзак 0/1 і необмежений рюкзак | використана місткість | *BeetleBag*, *Charlie New PC* | `knapsack01` |
| Розмін монет (кількість способів / найменше монет) | сума | *Visit Egypt* | `coin_ways`, `coin_min` |
| Найдовша зростаюча підпослідовність (LIS) | довжина → найменший останній елемент | | `lis_length` |
| LCS, відстань редагування, вирівнювання | префікси (i, j) | *Squared Gaps* | `lcs_length`, `edit_distance` |
| Шляхи в сітці | клітинка | *Ice Cubes*, *Lion Territory* | |
| Інтервали / зважене планування | сортування за кінцем + двійковий пошук | *Telescope Scheduling* | |
| DP на бітових масках | підмножина предметів | *Preparing for Xtreme 12.0*, TSP | `tsp` |
| DP на дереві | вершина (спершу сини) | *Merchant Association* | порядок із `tree.h` |
| DP за цифрами | (позиція, інформація, tight) | *Happy Numbers*, *Four Piles* | |
| Підрахунок за модулем p | кількість об’єктів | *Ordered Permutations* | |

### 7.2 Задача про рюкзак детально

Приклад із [`examples/knapsack.c`](../../examples/knapsack.c) — `f[i][c]` означає найкращу
цінність, яку можна отримати з перших i предметів у межах місткості c:

```c
for (int i = 1; i <= n; i++)
    for (int c = 0; c <= W; c++) {
        f[i][c] = f[i - 1][c];                                   /* пропустити предмет i */
        if (c >= w[i] && f[i - 1][c - w[i]] + v[i] > f[i][c])    /* взяти предмет i */
            f[i][c] = f[i - 1][c - w[i]] + v[i];
    }
```

Зворотний прохід від `f[n][W]` (предмет узято там, де `f[i][c] != f[i-1][c]`)
відновлює вибрані предмети. Якщо зберігати лише один рядок, перебирайте `c` **у спадному порядку**, щоб кожен
предмет використовувався щонайбільше один раз; перебір у зростаючому порядку дає необмежений варіант.

### 7.3 DP на бітових масках

Для n ≤ 20 підмножина — це ціле число-маска. Задача комівояжера
([`examples/tsp.c`](../../examples/tsp.c), `tsp` у [`dp.h`](../../lib/dp.h)):
`dp[mask][v]` = найдешевший шлях, що відвідав рівно вершини з `mask` і закінчується у `v`;
продовжуємо його невідвіданою вершиною `u`: `dp[mask | 1<<u][u] = min(dp[mask][v] + d[v][u])`.
O(2^n · n²).

### 7.4 DP за цифрами

«Скільки чисел у [A, B] мають властивість P?» = count(B) − count(A−1).
Будуйте число цифра за цифрою зліва направо; стан — це (позиція, усе, що потрібно для P,
`tight` = префікс досі збігається з межею). З
[`examples/digit_dp.c`](../../examples/digit_dp.c) (сума цифр ділиться на K):

```c
static ll go(int pos, int sum, int tight) {
    if (pos == nd) return sum == 0;
    if (!tight && seen[pos][sum]) return memo[pos][sum];
    int limit = tight ? dig[pos] : 9;
    ll res = 0;
    for (int d = 0; d <= limit; d++) res += go(pos + 1, (sum + d) % K, tight && d == limit);
    if (!tight) { seen[pos][sum] = 1; memo[pos][sum] = res; }
    return res;
}
```

### 7.5 Як пришвидшити DP

- Сума за діапазоном попередніх станів → зберігайте префіксні суми рядка DP.
- Мінімум/максимум у ковзному діапазоні станів → монотонний дек.
- Потрібен лише попередній рядок → два рядки (`lcs_length`).
- Переходи, що є фіксованим лінійним відображенням, застосованим n разів (n величезне) → піднесення
  матриці до степеня (розділ 11.4).

## 8. Графи

### 8.1 Подання

[`graph.h`](../../lib/graph.h) зберігає списки суміжності в масивах («forward star»):

```c
g_init(n + 1);                 /* вершини 1..n */
g_add2(u, v, w);               /* неорієнтоване ребро (g_add для орієнтованого) */
G_EACH(e, u) {                 /* усі ребра, що виходять з u */
    int v = g_to[e];
    ll w = g_w[e];
}
```

Матриця суміжності `int adj[N][N]` підходить для n ≤ 2000. Сітка — це граф,
вершини якого — клітинки; використовуйте безпосередньо [`grid.h`](../../lib/grid.h) (масиви напрямків `DR4/DC4`,
`IN_GRID`, `grid_bfs`, `grid_regions` для заливки областей (flood fill)).

### 8.2 Обходи

- **Пошук у ширину (BFS)** дає найкоротші шляхи, коли кожне ребро має вагу 1
  (`bfs`, `bfs_multi` для кількох джерел одночасно — наприклад, відстань до
  найближчого привида, *Invisible Ghosts*). Лабіринт: [`examples/grid_bfs.c`](../../examples/grid_bfs.c).
- **Пошук у глибину (DFS)** заходить якомога глибше: компоненти, цикли, топологічний порядок.
  Рекурсивна форма найзрозуміліша, але глибина рекурсії дорівнює довжині шляху:

```c
static int vis[MAXN];
static void dfs(int u) {          /* годиться для глибини до ~10^4..10^5 */
    vis[u] = 1;
    G_EACH(e, u) if (!vis[g_to[e]]) dfs(g_to[e]);
}
```

- **Пошук у просторі станів**: «граф» може бути неявним — позиції на дошці, комбінації
  замка, набори каменів. Закодуйте стан цілим числом (бітова маска, десяткові
  цифри) і виконуйте по ньому BFS (*Binary Quilts*, *Magical Stones*, *Combo Lock Redux*).

### 8.3 Найкоротші шляхи

| Ваги ребер | Алгоритм | Складність | Бібліотека |
|---|---|---|---|
| усі 1 | BFS | O(V+E) | `bfs` |
| 0 або 1 | 0-1 BFS (дек) | O(V+E) | `bfs01` |
| невід’ємні | Дейкстра з купою | O(E log E) | `dijkstra` + `build_path` |
| від’ємні, без від’ємного циклу | Беллман–Форд | O(VE) | `bellman_ford` |
| усі пари, V ≤ 400 | Флойд–Воршелл | O(V³) | `floyd` |

Алгоритм Дейкстри коротко: щоразу беріть із купи найближчу необроблену вершину
й виконуйте релаксацію її ребер; пропускайте застарілі записи в купі. Див.
[`examples/dijkstra.c`](../../examples/dijkstra.c). Додаткові умови («не більше k
безкоштовних ребер», «залишок пального», «перші п’ять вулиць різні») стають додатковими
координатами стану: запускайте алгоритм Дейкстри на вершинах (місто, k).

### 8.4 Інші класичні алгоритми

- **Мінімальне кістякове дерево (MST)** (Крускал): відсортуйте ребра, додавайте ребро, якщо воно з’єднує дві
  компоненти (система неперетинних множин, DSU). [`examples/kruskal.c`](../../examples/kruskal.c). Варіанти:
  максимальне кістякове дерево (сортування за спаданням), шляхи з вузьким місцем (*Xtreme
  Teleportation*), ребра, що належать хоча б одному / усім MST (*National Highway System*).
- **Топологічний порядок** (Кан, `toposort`): щоразу виводьте вершину без
  вхідних ребер; якщо виведено менше ніж n вершин, у графі є цикл (*King's Order*).
  Динамічне програмування (DP) на DAG виконують саме в цьому порядку.
- **Компоненти сильної зв’язності (SCC)** (`scc`, Тар’ян): взаємна досяжність;
  компоненти утворюють DAG.
- **Мости і точки зчленування** (`bridges`): ребра / вершини, видалення яких
  порушує зв’язність графа. Ребро можна зробити одностороннім, зберігши сильну
  зв’язність, тоді й лише тоді, коли воно не є мостом (*Bearcity Renting*).
- **Перевірка на дводольність** (`bipartite`): розфарбування у 2 кольори за допомогою BFS; воно неможливе тоді й лише тоді, коли є цикл непарної довжини.

### 8.5 Потоки і паросполучення

[`flow.h`](../../lib/flow.h): `max_flow` (Дініц), `bipartite_matching` (Кун),
`mcmf` (максимальний потік мінімальної вартості).

Прийоми моделювання:

- **Призначення** (працівники ↔ роботи): джерело → кожен працівник (пропускна здатність 1) → дозволені роботи
  (пропускна здатність 1) → стік (пропускна здатність 1). Максимальний потік = максимальне паросполучення
  ([`examples/matching.c`](../../examples/matching.c)). Якщо є вартості, використовуйте `mcmf`.
- **Робота, що приймає до c працівників**: пропускна здатність c на ребрі робота → стік (нори
  місткістю два Diglett, *Gotta ~ Catch 'Em All*).
- **Пропускні здатності вершин**: розділіть v на v_in → v_out і задайте пропускну здатність цьому ребру.
- **Мінімізація максимальної вартості призначення**: двійковий пошук за межею,
  залишайте лише дешевші ребра, перевіряйте наявність досконалого паросполучення (*Finding Shelter*).
- **Мінімальний розріз** = максимальний потік; після `max_flow` вершини з `fl_level[v] >= 0`
  лежать на боці джерела мінімального розрізу.
- Теорема Кеніга: у дводольних графах мінімальне вершинне покриття = максимальне паросполучення.

## 9. Дерева

Дерево має n−1 ребер і рівно один шлях між будь-якими двома вершинами. Більшість задач
на дерева починаються з підвішування дерева за корінь ([`tree.h`](../../lib/tree.h)):

```c
g_init(n + 1);
for (i = 0; i < n - 1; i++) { scanf(...); g_add2(u, v, w); }
tree_root(1);   /* t_par, t_dep, t_dist, t_sz, t_order (спочатку батьки), t_tin/t_tout */
```

- **Динамічне програмування (DP) на дереві**: у `t_order` сини йдуть після батьків, тому зворотний цикл
  обробляє спочатку синів — рекурсія не потрібна:

```c
for (int i = n - 1; i >= 0; i--) {      /* знизу вгору */
    int v = t_order[i];
    /* тут dp[v] уже обчислено; додаємо його до батька */
    if (t_par[v] >= 0) dp[t_par[v]] += dp[v];
}
```

- **Піддерево = суцільний відрізок**: піддерево вершини `v` — це `t_tin[v] … t_tout[v]`
  у прямому порядку обходу (preorder), тож суми/оновлення на піддереві стають запитами на відрізку
  в дереві Фенвіка або дереві відрізків (*He Loves Data Structures*).
- **Найнижчий спільний предок (LCA)** (двійкові підйоми, `lca_init`, `lca`, `kth_ancestor`): відстань
  `dist(a,b) = d(a) + d(b) − 2 d(lca)` ([`examples/lca.c`](../../examples/lca.c)).
- **Діаметр** (`tree_diameter`): найвіддаленіша вершина від будь-якої вершини є одним
  кінцем діаметра; найвіддаленіша від неї — другим кінцем. З’єднання двох дерев
  одним ребром: новий діаметр дорівнює max(d1, d2, r1 + r2 + 1), де r = ⌈d/2⌉
  (*Bridge Construction*).
- **Запити на шляхах з оновленнями** (`hld_build`, `hld_path`): важко-легка
  декомпозиція (HLD) розбиває будь-який шлях на O(log n) відрізків дерева відрізків
  (*ANDman*: добутки на шляхах; *Tree Queries 2*).
- **Підрахунок по всіх парах вершин**: рахуйте внесок кожного ребра —
  ребро, що розбиває дерево на частини розмірів s і n−s, лежить на s·(n−s) шляхах.
- **Перепідвішування (rerooting)**: обчисліть DP для кореня 1, потім переносьте корінь через кожне ребро,
  оновлюючи відповідь за O(1), — відповіді для всіх коренів за O(n).
- **Центроїдна декомпозиція** (немає в бібліотеці): для задач «порахувати шляхи з
  властивістю P» за O(n log² n).

## 10. Рядки

### 10.1 Рядки в C на практиці

Рядок — це масив `char`, що закінчується `'\0'`. `strlen` працює за O(n) — ніколи не викликайте її
в умові циклу. Корисні функції: `strcmp`, `strncmp`, `strcpy`, `strcat`,
`strstr` (пошук підрядка), `strchr`, `strtok` (розбиття, змінює рядок),
`sscanf` (розбір рядка), `sprintf` / `snprintf` (форматований запис у рядок),
а також із `<ctype.h>`: `isalpha`, `isdigit`, `isspace`, `tolower`, `toupper`.
Зіставляйте іменам числові ідентифікатори за допомогою `sm_id` з [`hashmap.h`](../../lib/hashmap.h).

**Шифри** трапляються майже в кожному випуску змагання (*Caesar Redux*, *Gaius Letters*,
*Book Cipher*, *Restaurant Cipher*). Шифр Цезаря зі зсувом k:

```c
for (int i = 0; s[i]; i++)
    if (isupper((unsigned char)s[i])) s[i] = (char)('A' + (s[i] - 'A' + k) % 26);
    else if (islower((unsigned char)s[i])) s[i] = (char)('a' + (s[i] - 'a' + k) % 26);
```

(Для розшифрування використовуйте `26 - k`. Якщо ключ невідомий, переберіть усі 26 і виберіть
той варіант, у якому частоти літер схожі на англійський текст або який містить відомі слова.)

### 10.2 Алгоритми

| Задача | Алгоритм | Складність | Бібліотека |
|---|---|---|---|
| Усі входження зразка | KMP (префікс-функція) | O(n+m) | `kmp_search` |
| Період рядка, грані | префікс-функція: період = n − π[n−1] | O(n) | `prefix_function` |
| Найдовший спільний префікс із кожним суфіксом | Z-функція | O(n) | `z_function` |
| Порівняння будь-яких двох підрядків | поліноміальне гешування | O(1) після O(n) | `hash_build`, `hash_sub` |
| Усі паліндроми | Манакер | O(n) | `manacher`, `longest_palindrome` |
| Багато слів: префікси, кількості | префіксне дерево (trie) | O(довжина) | `trie_insert`, … |
| Багато зразків у тексті | Ахо–Корасік | O(n + сумарна довжина) | `ac_build`, `ac_count` |

робить колізії практично неможливими; щоб порівнювати підрядки двох рядків,
гешуйте їхню конкатенацію.

**Дужкові послідовності** (*Tweedledum…*, *EDPS*, *Expression Evaluation*): підтримуйте

баланс ніколи не опускається нижче 0 і наприкінці дорівнює 0. Для кількох типів дужок
використовуйте стек відкритих дужок.

## 11. Математика і теорія чисел

### 11.1 Модульна арифметика

`(a + b) mod m`, `(a − b) mod m` (додайте m!), `(a · b) mod m` безпечні, поки
добуток уміщується в 64 біти (m < 3·10^9); інакше використовуйте `mulmod` (128-бітний) з
[`numtheory.h`](../../lib/numtheory.h). **Ділення** на `b` = множення на
обернений елемент: `b^(p−2) mod p` для простого p (мала теорема Ферма), `modinv` (розширений алгоритм Евкліда)
для будь-якого m, взаємно простого з b.

Швидке піднесення до степеня, O(log e):

```c
ll powmod(ll b, ll e, ll m) {
    ll r = 1 % m;
    b %= m;
    for (; e > 0; e >>= 1) {          /* перебираємо біти e */
        if (e & 1) r = r * b % m;
        b = b * b % m;
    }
    return r;
}
```

**Величезні показники степеня** (*Googolplex*, *Math Challenge*): при gcd(a, m) = 1
a^e ≡ a^(e mod φ(m)) (mod m) (теорема Ейлера); для простого m беріть e за модулем m−1.
Останні цифри степенів повторюються з коротким циклом — знайдіть його моделюванням.

### 11.2 Подільність і прості числа

- `gcd` (НСД, алгоритм Евкліда), `lcm(a, b) = a / gcd · b` (НСК; спочатку діліть!), `extgcd` розв’язує
  a·x + b·y = gcd(a, b), `crt2` об’єднує x ≡ a1 (mod m1), x ≡ a2 (mod m2).
- **Решето Ератосфена** (`sieve`): усі прості числа до `SIEVE_MAX` (за замовчуванням 10^6; 10^7 також
  уміщується в пам’ять) і найменший простий дільник кожного числа, після чого
  розкладання на множники за O(log x) ([`examples/sieve.c`](../../examples/sieve.c)).
- Окремі великі числа: пробне ділення до √n (`factor_trial`, n ≤ 10^12),
  тест Міллера–Рабіна (`is_prime`, будь-яке 64-бітне n).
- n має ∏(eᵢ+1) дільників; функція Ейлера φ(n) = n ∏(1 − 1/p).
- Кількість нулів у кінці n! у системі числення з основою B: розкладіть B на множники; формула Лежандра: показник p у
  n! дорівнює ⌊n/p⌋ + ⌊n/p²⌋ + … (*Factorial Zeros*).
- XOR чисел 1..n дорівнює n, 1, n+1, 0 для n mod 4 = 0, 1, 2, 3 (*RecXor*).

### 11.3 Довга арифметика

У C немає вбудованих великих цілих чисел. Спершу перевірте, чи задача справді потребує точних цифр
(часто потрібні лише остача, порівняння або логарифм). Якщо так,
[`bignum.h`](../../lib/bignum.h) зберігає числа в системі з основою 10^9: додавання, віднімання,
множення, ділення на мале число, виведення ([`examples/factorial.c`](../../examples/factorial.c)
виводить 50!).

### 11.4 Матриці

**Лінійні рекурентні співвідношення** f(n) = c₁f(n−1) + … + c_k f(n−k) для n до 10^18:
вектор останніх k значень множиться на фіксовану матрицю k×k, тож
f(n) отримуємо з M^n за O(k³ log n) ([`examples/fib_matrix.c`](../../examples/fib_matrix.c)).
Суми на кшталт Σ P^k k^Q (*Beautiful Summation*) вкладаються в ту саму схему з більшим
вектором стану.

**Метод Гаусса** (`gauss_mod`, `gauss_double`): розв’язує системи лінійних рівнянь,
обчислює визначники (за простим модулем) і ранги. Над GF(2) (рівняння з XOR,
головоломки «lights out») використовуйте XOR-базис із розділу 15.

## 12. Комбінаторика і ймовірності

[`combin.h`](../../lib/combin.h) попередньо обчислює факторіали та обернені факторіали
за простим модулем: `nCr`, `nPr`, `catalan` за O(1) після O(N)
([`examples/ncr.c`](../../examples/ncr.c)); `lucas` — для величезних n і малого простого модуля.

| Що рахуємо | Формула |
|---|---|
| упорядковані вибірки r елементів із n | n! / (n−r)! |
| підмножини розміру r | C(n, r) |
| мультимножини розміру r з n видів («кульки й перегородки») | C(n+r−1, r) |
| шляхи по ґратці вправо/вгору a×b | C(a+b, a) |
| правильні дужкові послідовності з n пар, двійкові дерева | Catalan(n) = C(2n, n)/(n+1) |
| перестановки мультимножини | n! / (n₁! n₂! …) |
| хоча б одна з кількох властивостей | формула включень-виключень Σ(−1)^(|S|+1)… |

- Правило Паскаля C(n, k) = C(n−1, k−1) + C(n−1, k) дає таблицю для малих n,
  навіть коли модуль не є простим.
- **Перестановки**: мінімальна кількість обмінів для сортування = n − (кількість
  циклів) (`perm_cycles`); мінімальна кількість обмінів сусідніх елементів = кількість інверсій.
  `next_perm` перебирає всі перестановки по порядку, `nth_perm` одразу переходить до k-ї.
- **Математичне сподівання** лінійне: E[X+Y] = E[X] + E[Y] навіть для залежних
  величин. Запишіть шукану величину як суму індикаторних величин і додайте їхні
  ймовірності (*New Casino Game*). Ймовірність «за модулем p» означає P·Q⁻¹ mod p.
- **Твірні функції**: кількість способів отримати суму s за кількох
  незалежних виборів — це коефіцієнт добутку їхніх многочленів;
  `poly_mul` у [`fft.h`](../../lib/fft.h) множить многочлени за модулем 998244353
  за O(n log n) (*Dice*, *Candy Shop*).
- Задачі на підрахунок часто легше розв’язати динамічним програмуванням (DP), ніж формулою;
  порівняйте обидва способи на малих прикладах.

## 13. Геометрія

Працюйте в цілих числах, якщо координати цілі ([`geom.h`](../../lib/geom.h)).
Головний інструмент — **векторний добуток**:

```c
ll cross3(Pt o, Pt a, Pt b) {      /* > 0: o→a→b повертає ліворуч (проти годинникової стрілки) */
    return (a.x - o.x) * (b.y - o.y) - (a.y - o.y) * (b.x - o.x);
}
```

Він дає орієнтацію, подвоєну площу трикутника, колінеарність (= 0), а на його
основі — перетин відрізків (`seg_intersect`), площу многокутника за формулою
Гаусса («шнурівки») (`polygon_area2` повертає подвоєну площу, точно), належність точки
многокутнику (`in_polygon`: метод променя, також розпізнає межу), опуклу оболонку
(`convex_hull`, монотонний ланцюг Ендрю; [`examples/convex_hull.c`](../../examples/convex_hull.c)).

- **Теорема Піка**: A = I + B/2 − 1 для многокутників із вершинами у вузлах ґратки; B = Σ gcd(|dx|, |dy|)
  за всіма сторонами (`lattice_interior`, *Polygon*).
- Відстані: порівнюйте квадрати відстаней (`dist2`) замість `sqrt`.
- Кола й еліпси: коли точну формулу знайти важко (площа об’єднання
  еліпсів, *Ellipse Art*), інтегруйте чисельно — розбийте полотно на вузькі
  смуги або дрібну сітку й підсумуйте.
- **Замітальна пряма (sweep line)**: відсортуйте події за x і рухайте вертикальну пряму,
  зберігаючи активні об’єкти у структурі даних (об’єднання прямокутників, перетини;
  *The Defensive Walls*). Підрахунок пар відрізків, що перетинаються, між двома
  паралельними прямими = підрахунок інверсій (*Laser Defense*), а кількість
  областей випливає з формули Ейлера V − E + F = 2.
- Допоміжні функції для дійсних чисел: `line_intersect`, `dist_pt_seg`; порівнюйте з допуском epsilon.

## 14. Теорія ігор

- **DP для виграшних і програшних позицій**: позиція виграшна тоді й лише тоді, коли
  деякий хід веде до програшної позиції; кінцеві позиції задаються правилами. Застосуйте
  мемоїзацію для всіх позицій (або ретроградний пошук у ширину (BFS), коли граф гри має цикли).
- **Мінімакс** для рахунку: гравець, що ходить, максимізує, суперник мінімізує
  (*The Gold-diggers*, *Let's Cheer Up Bob*); додайте мемоїзацію, коли позиції повторюються.
- **Нім**: купки a₁…a_k, за хід можна забрати будь-яку кількість з однієї купки — перший гравець
  виграє тоді й лише тоді, коли a₁ ⊕ … ⊕ a_k ≠ 0 (`nim_xor`).
- **Теорема Шпрага–Ґранді**: кожна позиція неупередженої гри має число Ґранді
  g = mex{g позицій, досяжних за один хід}; g = 0 означає програшну позицію, а сума
  незалежних ігор має число Ґранді = XOR чисел її частин
  ([`examples/grundy.c`](../../examples/grundy.c), `grundy_subtraction`, `grundy_dag`).
- Виведіть таблицю виграшних/програшних позицій для малих розмірів — закономірність
  (періодичність, діагоналі як у грі Вітгоффа, як у *Queen*) зазвичай підказує формулу.

## 15. Бітові операції

| Вираз | Значення |
|---|---|
| `x >> i & 1` | i-й біт x |
| `x \| (1 << i)`, `x & ~(1 << i)`, `x ^ (1 << i)` | встановити / скинути / інвертувати біт i |
| `x & -x` | молодший одиничний біт (`LOWBIT`) |
| `x & (x - 1)` | x без молодшого одиничного біта; 0 тоді й лише тоді, коли x — степінь двійки |
| `__builtin_popcountll(x)` | кількість одиничних бітів (`POPCOUNT`) |
| `__builtin_ctzll(x)`, `63 - __builtin_clzll(x)` | кількість молодших нулів, номер старшого біта (`log2_floor`) |
| `1LL << 40` | 64-бітовий зсув (звичайний `1 << 40` спричиняє переповнення) |

- **Підмножини**: маски 0 … 2^n − 1; усі підмаски `mask`:
  `for (s = mask; s; s = (s - 1) & mask)` (`FOR_SUBMASKS`); для всіх масок разом — 3^n кроків.
- **Сума за підмножинами** (`sos_subsets`): для кожної маски — сума за всіма її
  підмасками за O(n 2^n) — кількість команд, що покривають усі теми (*Xtreme Teams*).
- **XOR-базис (лінійний базис)** (`XorBasis` у [`bits.h`](../../lib/bits.h)): метод Гаусса
  над GF(2). Максимальний XOR підмножини, чи можна отримати x, і кількість
  різних значень XOR підмножин (2^rank). XOR випадкової підмножини рівномірно
  розподілений на лінійній оболонці базису (*Do you know Expectation?*).
- **Двійкове префіксне дерево (binary trie)** (`bt_*` у [`trie.h`](../../lib/trie.h)): максимум `x ^ y` для y
  з динамічної множини, кількість таких y, що `x ^ y < k`.
- OR / AND лише додають / прибирають біти: на відрізку, що розширюється, OR змінюється щонайбільше
  30 разів — це корисно в задачах «сума за всіма підмасивами».

## 16. Інтерактивні задачі

Система перевірки відповідає на ваші запити, поки ваша програма працює. Правила:

1. Скидайте буфер після кожного виведеного рядка, інакше система перевірки його не отримає:
   `printf(...); fflush(stdout);` — `ASK(...)` у [`interactive.h`](../../lib/interactive.h).
2. Читайте відповіді через `scanf`; завершуйте роботу, коли система перевірки повідомляє `-1` (некоректний запит).
3. Рахуйте свої запити: обмеження на їх кількість — частина умови (log₂ від розміру діапазону для
   двійкового пошуку, теоретико-інформаційні оцінки для головоломок зі зважуванням).

[`examples/guess.c`](../../examples/guess.c) знаходить загадане число за допомогою запитів «чи X ≥ y?»:

```c
while (lo < hi) {                       /* X лежить у [lo, hi] */
    ll mid = lo + (hi - lo + 1) / 2;
    ASK("? %lld\n", mid);
    if (reply_int()) lo = mid; else hi = mid - 1;
}
ASK("! %lld\n", lo);
```

Тестуйте локально з невеликою програмою перевірки, з’єднаною через два іменовані канали
(див. [`examples/judge_guess.c`](../../examples/judge_guess.c) і
[`tests/run_examples.sh`](../../tests/run_examples.sh)).

## 19. Повний перебір і перебір із поверненням

Коли n мале або щоб отримати часткові бали, перебирайте всі варіанти:

```c
static int n, choice[20];
static void search(int i) {            /* вибір для елемента i */
    if (i == n) { /* оцінити повний вибір */ return; }
    for (int c = 0; c < 2; c++) {      /* кожен варіант для елемента i */
        choice[i] = c;
        if (/* частковий вибір ще може перевершити найкращий */ 1) search(i + 1);
    }
}
```

- **Відсікання**: припиняйте гілку, щойно вона не може бути коректною або не може перевершити
  найкращу знайдену досі відповідь; спершу пробуйте перспективні варіанти.
- **«Зустріч посередині»**: розділіть n ≤ 40 елементів на дві половини, переберіть 2^20
  сум кожної, відсортуйте одну половину й шукайте доповнення двійковим пошуком.
- **Ітеративне заглиблення / пошук у ширину (BFS) за станами**, коли потрібна найкоротша послідовність
  ходів (*Puzzle of Rooks*, *Digits swap*).
- **Контроль обмеження часу** в оптимізаційних задачах: у циклі `while (elapsed_sec() < 1.8)`
  покращуйте евристичну відповідь (`util.h`).
- Рандомізація допомагає в евристиках (`rng_next`, `shuffle_int`).
